# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A FiveM (GTA V) roleplay server on the **Qbox** framework (`qbx_core`) with the scripts of the Qbox txAdmin recipe (jobs, garages, HUD, illenium-appearance, …), the **ox** stack (oxmysql, ox_lib, ox_target, ox_doorlock, ox_fuel), our own inventory `city_inventory` (replaces ox_inventory) and pma-voice. All code is Lua 5.4 resources loaded by FXServer; there is no build step. `bash scripts/check.sh` checks our `[local]` resources without a server (Lua syntax, UI JavaScript, locale JSON, and the plain-Lua unit tests in `tests/<resource>/`, run with luajit); the rest is verified by restarting the resource on a running server.

## Running the server

FXServer is x86_64 only and **does not run on Apple Silicon** (crashes under Rosetta and QEMU). On a Mac, edit resources here and run the server on an x86_64 Windows/Linux machine.

```sh
cp .env.example .env                 # set CFX_LICENSE_KEY and MYSQL_ROOT_PASSWORD (alphanumeric only)
docker compose up -d --build         # FXServer + txAdmin, and MariaDB
docker compose logs fxserver | grep -i pin   # txAdmin PIN, then http://localhost:40120
docker compose logs -f fxserver
docker compose restart fxserver
docker compose build --no-cache fxserver && docker compose up -d   # update FXServer build
```

In the txAdmin wizard choose **Existing Server Data** → `/server-data`, config `server.cfg` — not a recipe, which installs its own copy under `/txData` that ignores this repo. txAdmin starts the server (the image entrypoint has no `+exec`).

Docker only imports `qbx_core.sql` into a new database. Create the other resources' tables with `scripts/import-sql.sh` (safe to re-run; run it after adding resources that bring SQL).

After editing a resource, reload it from the txAdmin console or in-game: `ensure <resource_name>` (or `restart`).

The full run guide (setup, updates, backups, troubleshooting) is `docs/docker.md`; keep it in step with changes to the Docker setup.

## Architecture

- **`server-data/server.cfg`** is the single entry point. It `exec`s `secrets.cfg`, then `ensure`s core resources in a fixed order (`oxmysql` → `ox_lib` → `qbx_core` → `city_ui` → `city_inventory` → `ox_inventory` → `ox_target`), then whole groups: `[ox]`, `[qbx]`, `[standalone]`, `[voice]`, `[assets]`, `[maps]`, `[local]`. Convars follow the Qbox recipe's `server.cfg` / `ox.cfg` / `voice.cfg`. Dropping a resource into one of those group folders is enough to start it. Framework/inventory convars (`qbx:enableBridge`, `inventory:framework "qbx"`, `inventory:accounts` left unset so it defaults to `["money"]`: the cash item is the player's cash) and ACE permissions (`group.admin` > `group.mod` > `group.support`) are also set there.
- **Secrets**: `secrets.cfg` is gitignored. In Docker, `docker/fxserver/entrypoint.sh` regenerates it on every start from env vars (license key, `mysql_connection_string` pointing at host `mariadb`). If `CFX_LICENSE_KEY` is empty, an existing mounted `secrets.cfg` is used instead.
- **Docker**: `docker-compose.yml` is the only way the server is run. It bind-mounts `./server-data` into the container, so the server runs the repo's files (FXServer itself is downloaded inside the image, never from `artifacts/` — Windows filesystems break its symlinks). MariaDB imports `qbx_core/qbx_core.sql` only when its volume is first created.
- **Third-party resources are vendored** (committed). `scripts/install-resources.sh` re-downloads everything the Qbox txAdmin recipe (`qbox.yaml`) installs except ox_inventory, wiping each target folder first, copies the qbx_invimages item images into `city_inventory/web/images`, then applies `scripts/patches/<resource>.patch`. Don't hand-edit those resources without a patch, or the change is lost on the next update: edit, then `bash scripts/make-patch.sh "server-data/resources/[group]/<resource>"`, which rebuilds the resource's whole patch from upstream (a bare `git diff` would drop the existing patch's changes).
- **`city_inventory`** (`[local]/`) replaces ox_inventory. qbx_core is hard-wired to ox_inventory, so `scripts/patches/qbx_core.patch` points it at `city_inventory`, which provides the same server/client export names and arguments (`AddItem`, `RemoveItem`, `GetItemCount`, `Search`, …) and the same `data/items.lua` / `data/weapons.lua` format (qbx_core loads those files too, so they must stay plain data). Make items usable with `exports.qbx_core:CreateUseableItem`. Inventories are saved in the `city_inventories` table, keyed by citizenid. `data/items.lua` is Qbox's item list; its ox-style `client.status/anim/prop/usetime/event/add/remove` fields work (`server/use.lua`, `client/use.lua`). Item names are case-insensitive (`WEAPON_PISTOL` = `weapon_pistol`) and stored as written in `data/`. Dropping one item onto another combines them on the server (`server/actions.lua` `combine`): ammo loads a gun, an attachment goes on a gun (kept in `metadata.components`), and `Config.Recipes` pairs craft; a gun's weight includes its attachments and loaded rounds (`shared/weight.lua`). Its `server/compat.lua` / `client/compat.lua` hold the less common ox exports and fire ox's events (`ox_inventory:currentWeapon`, `itemCount`, `openedInventory`). Stashes work (`RegisterStash`, `openInventory('stash')`, `forceOpenInventory`, `registerHook('openInventory')`; `server/stashes.lua`, shown as a second panel and saved in `city_inventories` as `stash:<id>`). Shops work too: `data/shops.lua` (ox_inventory's default stores, with blips and ox_target zones from `client/shops.lua`) plus `RegisterShop` from scripts (ambulance armory); items are bought by dragging them out of the shop panel, paid from `Config.ShopAccounts` or an item `currency`, with licence/grade/stock checked in `server/shops.lua`. Ground drops (`server/drops.lua`, bags from `client/drops.lua`, in memory for `Config.DropMinutes`; `CustomDrop`/`CreateDropFromPlayer`) and player trades (`server/trades.lua`: ox_target "Trade" on a player, both offers held aside as small inventories until both accept) work too; `server/other.lua` keeps one of stash/shop/ground/trade/search open per player. Trunks and gloveboxes are stashes keyed by plate (`server/vehicles.lua`, sizes in `Config.VehicleStorage`; saved only for cars in `player_vehicles`), opened with TAB at a car's back or inside it. Searching players (`openNearbyInventory`, `openInventory('player', id)`; `server/searches.lua`) shows the target's inventory as the second panel: police on duty (`Config.SearchJobTypes`) search anyone close (city_police's `openInventory` hook makes a suspect who isn't cuffed, down or hands up accept first), anyone may rob a player who is cuffed, down or has `state.handsup`, and staff with `Config.SearchStaffAce` on admin duty open anyone's from anywhere. The `money` item (`Config.CashItem`) **is** the player's cash: qbx_core mirrors city_economy's cash balance into it, scripts add or take it through qbx money (`server/cash.lua`), and every move inside the inventory (ground, trade offers, stashes, trunks, another player, death drop, clearing, expiry) is written to the ledger first by `server/cashflow.lua` (the hook in `Inventory.transfer`; if the ledger refuses, the item does not move). Scripts can't add/remove/set cash in stashes, drops or trades, and `players.sync` puts a pocket back to the ledger value (with a flag) if they ever differ.
- **`ox_inventory`** (`[local]/`) is a stand-in, not the real resource: two files that forward ox's export names to `city_inventory`, for the ~40 vendored scripts that call `exports.ox_inventory` and for ox_fuel, which needs a resource named ox_inventory at version ≥ 2.30.0. It has no logic of its own; our `[local]` resources call `exports.city_inventory` directly.
- **`city_economy`** (`[local]/`) owns all money: an append-only double-entry ledger (`economy_accounts`, `economy_ledger`) with atomic, locked postings. `qbx_core`'s `AddMoney` / `RemoveMoney` / `SetMoney` for `cash` and `bank` ask it first (`scripts/patches/qbx_core.patch`) and `PlayerData.money` is only a mirror (`SetPlayerData('money')` is refused, `crypto` is gone). It only accepts the resource + reason pairs listed in `city_economy/server/config.lua` `sources`; anything else is refused and logged, so a script that pays or charges must pass a reason and be added there. New characters get $2,000 cash and $498,000 bank from it (V1 test amounts; qbx_core pays every job $20,000 every 10 minutes). Rules and design: `PROMPT_ECONOMIA_FIVEM.md`, `BANCO_DESIGN.md`; blocked scripts are listed in `docs/scripts/issues.md`. **`city_bank`** is the bank on top of it: branches (banker NPC, fingerprint, panel with accounts, cards, transfers, loans, bills, history, staff tab), ATMs, the `bank_card` and `pos_terminal` items and a scheduler (bills, card cycles, installments, savings yield). It moves money only through `city_economy` `Bank*` exports (reasons `bank-...`, callable only from city_bank); rules and numbers are in `city_bank/server/config.lua`. Renewed-Banking was removed. Other resources bill players with `exports.city_bank:CreateBill` only if listed in its `settings.billers`. The phone's Wallet (`city_phone_wallet`) uses the same panel handlers through `city_bank:app:<name>` (`access.allowApp` in `server/app.lua`: phone item and not down instead of branch + fingerprint); a card purchase over the card's own limit asks its holder on the phone (`server/approvals.lua`, `settings.app.approvalSeconds`) and is paid only if approved.
- **`city_hospital`** (`[local]/`) replaces qbx_ambulancejob; qbx_medical still owns injuries and the death state bag (`qbx_medical:deathState`, set by the client). city_hospital tracks downed players on the server from that bag, turns off qbx_medical's own respawn, and owns the downed screen (NUI), `/finalizado` (character metadata `finalized`, which only a real revive clears: `scripts/patches/qbx_medical.patch` fires `qbx_medical:server:revived`), hospital respawn, beds, reception, the NPC ambulance and the EMS job. Other medic scripts must check `exports.city_hospital:IsFinalized(src)` before reviving. Fees are `hospital-*` reasons; unpaid ones become bills. Prices and timers are in `server/config.lua`. The **EMS** tablet app (`web/app/`, `server/app/`, `client/app.lua`, a copy of the Mechanic app: docs/work-apps.md) has a dashboard, the EMS calls of `server/sos.lua` (accept sets the GPS, whoever accepted closes it; a new one notifies EMS on duty and badges the icon), Management (job offers by server id, grades, fire) and Records: every EMS revive and bill in `city_hospital_records`, with the reference prices of `server/config.lua` `billing`.
- **`city_garages`** (`[local]/`) replaces qbx_garages. Garages are unified: a car parked at any garage of its kind (`car`/`air`/`sea`, from the qbx_core vehicle `type`) can be taken out at any other, so `player_vehicles.garage` is only where it was last parked. Players open a garage with ox_target on its ped and park with ox_target "Park vehicle" on their empty car inside the parking area; the NUI lists their cars with search, favorites (client KVP) and the model's picture (`Config.ImageUrl`, docs.fivem.net) and condition. Impound lots (`depot = true`) return cars left out that are no longer in the world for a fee (`garage-depot`, cash then bank); police-impounded cars (`state = 2`) are not theirs. Other scripts add garages with `exports.city_garages:RegisterGarage(id, { label, kind, coords, spawns, canAccess, ... })`; qbx_properties does it for house garages (`scripts/patches/qbx_properties.patch`).
- **`city_dealership`** (`[local]/`) replaces qbx_vehicleshop: Premium Deluxe Motorsport only (no boat or air shop). ox_target on a showroom computer (`Config.Computers`) opens the catalogue NUI: every car of `Config.Categories` from qbx_core's vehicle list (price from there, `Config.Blocklist` skipped), photo from `Config.ImageUrl`, stats from the model's handling natives, test drives (server-spawned on the lot, deleted after `Config.TestDrive.seconds` or when too far). Buying in full (cash or bank) or financed (`server/quote.lua`: down payment, interest, installments) is `dealership-*` reasons; the car is created parked at the `pdm` garage of city_garages. Each installment is a city_bank `loan` bill issued with `exports.city_bank:IssueBill` (offline-safe, for `settings.billers`); every minute `server/finance.lua` reads the bills' status in `bank_bills`, closes paid-off financings and repossesses the car (deleted from `player_vehicles`) once `Config.Finance.repoAfter` bills are overdue. Exports `FinanceBalance` / `IsFinanced`, for scripts that sell or trade owned cars. The old `vehicle_financing` table is no longer read.
- **`city_mechanic`** (`[local]/`) replaces qbx_mechanicjob and qbx_customs: the `mechanic` job at LS Customs (Burton), with duty, a shared stash, work vehicles and the tuning bay. A mechanic on duty drives the car into `Config.Bay` and presses the keybind (E) to open the NUI menu; every choice is previewed on the car (the driver owns the entity), and on confirm the server checks the cart against `shared/catalog.lua` (keys are ox_lib vehicle property names), prices it from `Config.Prices`, pays it from the mechanic job's account with `exports.city_bank:ChargeJob` (only resources in city_bank `settings.jobPurchases`; reason `bank-job-purchase`, money goes to `WORLD_SINK`) and writes the paid changes into the car's saved props itself (`qbx_vehicles` `SaveVehicle`). For the V1 `Config.Features.chargeJob` is off (parts are free) and staff with `Config.StaffAce` use the bay without the job, always free and written to the staff log. The mechanic charges the customer separately (bill or card machine). `repairkit`, `advancedrepairkit` and `cleaningkit` are usable by anyone next to a car; mechanics on duty fix more. Anyone can "Check vehicle" (ox_target on any car, `client/inspect.lua`): a read-only list of performance levels, turbo, body, engine and fuel. qbx_mechanicjob's part wear (radiator, axle, ...) is gone; `player_vehicles.status` / `drivingdistance` are no longer read. The **Mechanic** tablet app (`web/app/`, `server/app/`, `client/app.lua`) has a dashboard, the 555 calls (read and answered through city_dispatch's callbacks; a new one notifies mechanics on duty and badges the icon, from city_dispatch's `city_dispatch:server:callsChanged` event and `OpenCount` export), Management (the whole team sees every mechanic and who is online; the boss sends a job offer by server id that the player accepts on screen, changes grades and fires) and the bay's service history (`city_mechanic_services`, written on every confirmed tune) with the price list. It is the template for the other job and gang apps: `docs/work-apps.md`. The kits and a jerry can are sold to anyone by a shopkeeper at LS Customs (`MechanicStore` in city_inventory's `data/shops.lua`).
- **`city_militech`** (`[local]/`) is the Militech tuner: using the `militech_tuning` item (not consumed) from the driver seat of a stopped car opens a Forza-style NUI that changes CHandlingData fields. Sliders are changes from the car's own handling (`Config.Params`: ranges, steps and the fields each one moves); `shared/tuning.lua` checks a setup, works out the resulting handling and the stats/PI (tested in `tests/city_militech/`). The server keeps the checked setup on the car's `militech` state bag and saves it per `player_vehicles.id` in `city_militech_tunes`; only the driver's client applies it (handling is local per client), reading the car's stock values first, and a driver getting into a car without the bag asks the server to load it. **`city_militech_staff`** is the staff version (`staff_militech` item + `Config.Ace`, default `group.admin`): absolute values for every field in its `shared/fields.lua` (hard limits checked on the server, vectors as `{ x, y, z }`), kept on the `militechStaff` bag and in `city_militech_staff_tunes`, logged with `exports.city_staff:Log`. city_militech's client applies both bags: `militechStaff` replaces `militech` while it is set (field kind by name: `n`... int, `vec`... vector), and its client export `Stock(vehicle, fields)` gives the staff screen the same per-car stock values.
- **`city_phone`** (`[local]/`) replaces npwd. It opens from the `phone` item and always shows its user's own data (number = `charinfo.phone`; settings in metadata `phonesettings`). The player walks and drives with it open (`SetNuiFocusKeepInput`, with `Config.BlockedControls` off: mouse camera, attacking, pause); while a text field has focus, on the phone or in an app page (kit.js reports it with `city_phone:typing`), the keys go to the page instead. It is only the platform (lock screen, home, dynamic island, control center, multitask, Settings, notifications): every app is its own `city_phone_<app>` resource that calls `exports.city_phone:RegisterApp` on the client; the phone shows the app's page in a frame and passes `city_phone:context` / `city_phone:message` with postMessage, and the page calls its own resource's NUI callbacks. Old `qb-phone:*` mail and alert events become phone notifications (`server/compat.lua`, `client/compat.lua`). Ringing is the `phoneRinging` state bag (`exports.city_phone:SetRinging`), played by everyone nearby with Web Audio tones. `city_phone_calls` is the Phone app; it is the only resource that sets pma-voice call channels, and it puts back anyone who joins a call channel on their own, and exports `Contacts` / `ContactName` for other apps. Its contacts also list the city services from **`city_dispatch`** (`Config.Services`: 190 police, 192 EMS, mechanic), fixed and not editable: calling one (or dialing the number) opens a form (type, text, anonymous) and `exports.city_dispatch:Report` sends it with the caller's location to that job type on duty (phone notification with a Respond button, blip, `/calls`), or for EMS into city_hospital's calls (`exports.city_hospital:PhoneCall`). Responders are never named to the caller. `city_phone_messages` is Messages: chats keyed by phone number (so offline players get them later), groups, reactions, read receipts, and locations read on the server (live shares update a blip every few seconds; the route set on the map can be sent too, its point checked against `Config.MapBounds`). `city_phone_gps` is Maps: it has no map of its own but puts the phone away and opens the game's pause-menu map (`FE_MENU_VERSION_MP_PAUSE`), bringing the phone back when it closes, and its page shows or clears the route. Apps show unread counts with `exports.city_phone:SetBadge`. `city_phone_darkchat` registers DarkChat only while its client carries the `darkchat_usb` item (`RemoveApp` when it goes) and its server checks the item on every callback; rooms are joined by exact name (password hashed with `GetPasswordHash`), others only see aliases, and messages are deleted after `Config.MessageHours`. `city_phone_news` is Weazel News: only jobs in its `Config.Jobs` (reporter) on duty write; breaking news notifies every online player, at most once per `Config.BreakingCooldown` minutes per journalist; the author, the job's boss and `Config.StaffAce` delete (staff through `exports.city_staff:Log`). `city_phone_music` plays inside its own page (a hidden YouTube iframe player, or an `<audio>` for https audio links; app frames get `allow="autoplay"`), so only the owner hears it and it keeps playing with the phone closed until the app is closed from the switcher; searching by title goes through the server with the convar `youtube_api_key` (from `YOUTUBE_API_KEY` in `.env`), and pasted YouTube links get their title from oEmbed. App pages share one look through the kit in `city_phone/web/kit/` (`kit.css` + `kit.js` with icons, lists, avatars, sheets, nav bars, tab bar), loaded from `https://cfx-nui-city_phone/web/kit/`; use it for every new app. The phone size (70–130%) is a setting, also changed by dragging the phone's top-left corner. `city_phone_camera` (camera mode: scripted back and selfie cameras the player walks with, timecycle filters) asks `city_phone_photos` to take the picture; the server captures it with `exports.screencapture:serverCapture`, checks size and the 300-photo limit, and keeps it in `phone_photos` (the client never uploads an image). A photo can be the wallpaper (setting `wallpaperPhoto`); other apps read a character's photos with its `List` / `Data` exports. `city_phone_market` is Market: ads in `phone_market_ads` (the chosen photo is copied into the ad) and `phone_market_favorites`; publishing or renewing costs `Config.Fee` from the bank (city_economy reason `market-ad`), ads expire after `Config.Days`, `Config.MaxAds` per character, "Contact" opens the seller's chat in Messages, and `Config.StaffAce` removes any ad (written to the staff log through `exports.city_staff:Log`). `city_phone_social` is InstaPic: one account per character in `phone_social_accounts`, posts and 24-hour stories in `phone_social_posts` (the chosen photo is copied in), likes, comments and follows in their own tables; likes, comments and new followers notify the person on the phone, and `Config.StaffAce` removes any post or comment (staff log through `exports.city_staff:Log`). `city_phone_dating` is Matchy: profiles (`phone_dating_profiles`, age and gender from charinfo, up to 3 photos copied into `phone_dating_photos`), swipes, matches and a chat of their own; pages only see a profile's numeric id, never a citizenid or phone number.
- **`city_radio`** (`[local]/`) is the radio list on screen: while the player is in a pma-voice radio channel (`Player.state.radioChannel`) it shows the channel (`Config.ChannelNames`), the members and who is talking, from pma-voice's own client events; names come from its server (callsign from `exports.city_police:Callsign` + name), only for the asker's own channel. `/radiolist` hides it, `/radiolistmove` drags and resizes it (client KVP). mm_radio stays the radio device; radio talk is Caps Lock (`voice_defaultRadio`) because Left Alt is ox_target's.
- **`city_os`** (`[local]/`) is the iFruit tablet (`tablet` item, F2): lock screen, passcode, home, dock, notification center and the built-in Settings, and nothing else. Every app is its own resource: it registers on the server with `exports.city_os:RegisterApp` (glyph + colors icon, its own `web/` page loaded in an iframe, access by job/gang/staff/unlock), styles its page with `city_os/web/kit/kit.css` + `kit.js`, and uses `Notify`/`SetBadge`/`Unlock` (and, on the client, `OpenApp(appId, args)` to open the tablet on its own app with args, after the passcode if there is one); its own server events still check access. Tablet settings and the bcrypt passcode are saved per serial in `city_os_tablets`; a player's own wallpaper link stays in client KVP. Design: `docs/city-os.md`. Job and gang apps also load the work app shell (`city_os/web/kit/workapp.css` + `workapp.js`, the Staff/MDT layout with `WorkApp.shell`); see `docs/work-apps.md`.
- **`city_staff`** (`[local]/`) is the first tablet app, **Staff**, and replaced qbx_adminmenu: player list and actions, `/report` reports, warnings (`city_staff_warnings`), bans (qbx_core's `bans` table), the staff log (`city_staff_log`), noclip/names/blips and vehicles. Staff tools live only in the app, with no in-game commands; `qbx_core.patch` also removes qbx_core's admin commands and turns admin duty off (`requireOptIn = false`, no `/optin`, so `IsOptin` is always true). Levels are the `support` < `mod` < `admin` ACEs; what each may do is `Config.Permissions`, checked by every server callback (`server/staff.lua` `staff.register`). Design: `docs/city-staff.md`.
- **`city_builder`** (`[local]/`) is the **Builder** tablet app (`Config.Ace`, default `admin`): its button opens a freecam editor (its own NUI) to place props, chosen from `web/props.txt` (every GTA prop, from DurtyFree's ObjectList dump, LODs left out) plus the `.ydr`/`.yft` names `server/streams.lua` finds under `resources/` at start (`io.popen` find/dir; vehicles left out). Rows show a turning see-through preview in the game, not a picture. Props are moved with the cursor (raycast), arrow/rotation keys or exact numbers, saved in `city_builder_props` (with `city_builder_groups`, shown/hidden, moved or deleted as a whole) and broadcast to every client, which spawns them locally (not networked) within `Config.RenderDistance` of the camera (`client/world.lua`, 100 m grid). Clicking a map object hides that model there for everyone (`CreateModelHideExcludingScriptObjects`, `city_builder_hides`). Every change checks the ACE + admin duty, `shared/validate.lua` (tested) and that the point is within `Config.MaxCamDistance` of the builder's character, and goes to the staff log; undo/redo (`client/history.lua`) replays changes through the same server calls. "Export ymap" on a group (or the ungrouped props) writes a CodeWalker CMapData XML (`shared/ymap.lua`, tested: rotations stored inverted as ymaps keep them) to `city_builder/exports/` (gitignored) and the clipboard, then deletes those props from the database: from then on they live in a `.ymap` streamed by a `[maps]` resource. Hidden map props aren't exported.
- **`city_police`** (`[local]/`) replaced qbx_police: the LSPD job and the **MDT** tablet app. Only the `police` job exists (BCSO and SASP are removed by `qbx_core.patch`, which also makes officers clock in). It owns the police calls (`exports.city_police:Alert`, `PhoneCall` from city_dispatch for 190, the panic button), cuffs (`metadata.ishandcuffed`, set only on its server; `exports.city_police:SetCuffed` / `IsCuffed`), escort, objects and spike strips (`GlobalState.policeSpikes`), ground evidence (casings, blood, fingerprints; bags analyzed in the MDT), automatic calls for shots fired in town and officer down (`server/alerts.lua`), tackling, zip ties and head bags (`zipTied` / `headBag` state bags, usable by anyone on a player who gave up), the crowbar, the patrol car radar and megaphone, BOLOs and live bodycams in the MDT, MDT Management (every officer sees the roster; the chief sends job offers by server id that the player accepts on screen, changes ranks, fires), MDT Cases (tags, people with roles, charges per criminal, photos copied from the officer's phone into `city_police_case_photos`, drafts kept in the page's localStorage) and the Prison tab (inmates from `exports.city_prison:Inmates`, arrests with a case attached and a reduction, `records.reduce`), the station wardrobe (uniforms, own clothes kept in `city_police_wardrobe`), the `police_badge` item, blips of the other officers on duty, security cameras, ankle monitors, speed cameras, impounds (`player_vehicles.state = 2` until released) and the records in its `city_police_*` tables. Fines, radar tickets and impound fees are city_bank bills, never direct money. It keeps the old qbx_police events vendored scripts still fire (`police:server:policeAlert`, `evidence:server:CreateFingerDrop` / `CreateBloodDrop`, `evidence:client:SetStatus`, `police:client:SendPoliceEmergencyAlert`, `police:SetCopCount`, the camera events). Weapons bought in a shop are registered by serial (city_inventory fires `city_inventory:server:boughtWeapon`; `exports.city_police:RegisteredWeapons(citizenid)`). An arrest shows the arrested screen and calls `exports.city_prison:Jail`. Other scripts add warrants with `exports.city_police:IssueWarrant`. Grades per action are `Config.Permissions`; design: `docs/city-police.md`.
- **`city_prison`** (`[local]/`) replaced xt-prison: Bolingbroke. Sentences are counted on the server (one month = one minute played inside, `server/config.lua`) in `city_prison_inmates`, with `city_prison_log` as history; `metadata.injail` only mirrors the months left and `Player(src).state.inPrison` says who is inside. Going in, the inmate goes off duty (and can't clock in), wears the uniform and their items go to a per-character `city_prison_locker` stash, except illegal ones and weapons not registered to them, which go to city_police's evidence locker; cash stays in the pocket. Jobs (cleaning, kitchen, electrical) take months off up to half the sentence; water and a food tray feed them; hidden spots give parts that combine (city_inventory `Config.Recipes`) into a shank, a gate jammer or a `burner_phone`. Leaving the circle is an escape: the time left times `escapeMultiplier` is owed, the police get a call and an MDT warrant, and the next arrest adds it. Gate terminals open ox_doorlock gates it creates by name. A downed inmate wakes in the prison infirmary (`exports.city_prison:Respawn`, called by city_hospital). Police on duty use the prison computer (list, set time, release, clear an escape; grades in `Config.ComputerGrades`). When the time is served the inmate is let out automatically: prison-made items stay inside and the locker comes back (the release desk only hands out what didn't fit). A burner phone is city_phone with its own number (in the item metadata), calls always hidden and only `Config.BurnerApps`; Phone and Messages get the number in use from `exports.city_phone:ActiveNumber` / `SourceByNumber`. Design: `docs/city-prison.md`.
- **`city_fishing`** (`[local]/`) is fishing, the first legal job: anyone with a `fishing_license` item of their own (metadata citizenid + expiry) sells at the fish market. Using a rod starts fishing on the client (power bar, cast, bite, the minigame page `web/index.html`), but the server owns the catch (`server/sessions.lua`: cast → hook → finish, with a session, timing and distance checks): the region comes from the bobber position (`server/regions.lua` polygons), what bites from `server/fish.lua` (server only: chances, hours, weather from Renewed-Weathersync's `GlobalState.currentTime` / `weather`, legendary spots), and size, stars (`metadata.quality`, fish stack per species + stars), XP and chest loot from `server/catch.lua`. Bait and tackle are put on the rod by using them (rod metadata `bait`, `tackle`, `durability`). XP, level (1-30) and the skill tree (`shared/levels.lua`) are in `city_fishing_profiles`, the collection in `city_fishing_collection`. The shop (licence, gear by level, repair, skill reset), market (dynamic price per species, `server/demand.lua`) and marina (boat rental) are NPCs with ox_lib menus; crab pots are saved in `city_fishing_pots` and anyone can pull them; frenzies (`GlobalState.fishingFrenzy`) and tournaments (schedule in `server/config.lua`, or staff from the app) run on a one-minute clock. Money is `fishing-*` reasons. The **Fishing** tablet app is `web/app/`. Design: `docs/city-fishing.md`.
- **`city_character`** (`[local]/`) replaces qbx_core's character menus (`qbx_core.patch` sets `useExternalCharacters = true`, so qbx_core's `client/character.lua` stays off; its `getCharacters` / `createCharacter` / `loadCharacter` / `deleteCharacter` callbacks are still the ones used). One NUI holds the select screen and the creator, with the ped in the lineup room under Mission Row (`Config.Studio`, scripted cameras and `Config.Lights`, solo session). The creator previews every change on the ped; the face is sculpted by dragging `Config.FacePoints` (head-bone offsets projected to the screen, each moving one or two of the 20 face features) or the 2D pads. Identity is asked last; `createCharacter` runs first, then `city_character:saveLook` sends the draft, which the server rebuilds and checks with `shared/appearance.lua` (tested; ranges, `Config.Blocked`, sex must match the character) and writes to `playerskins` in illenium-appearance's format, only when the character has no look yet (later changes are the clothing shop, barber and surgeon). A character with no look (left mid-way) goes back to the creator from the select screen. After saving: qbx_properties' starting apartment (`qbx_properties.patch` no longer opens illenium's creator there) or the default spawn; existing characters go to **`city_spawn`** (`exports.city_spawn:Open()`), which replaced qbx_spawn: a full-screen NUI with one column per `Config.Spots` entry and a scripted camera over the one pointed at. The server sends the list and gives the coords for the chosen id (once per character load); the last location is `PlayerData.position`, and a character that logged out jailed (`metadata.injail`), down or cuffed skips the picker and goes back there.
- **`city_clothing`** (`[local]/`) replaces illenium-appearance's clothing stores and barbers (`scripts/patches/illenium-appearance.patch` drops those two store types; tattoo, surgeon, outfit rooms and the police wardrobe stay on illenium). A clerk ped (ox_target, spawned with `lib.points`) at each `Config.Stores` entry opens the shop NUI: category tabs (`Config.Categories`: clothes or hair/beard/makeup), a grid of cards with a picture of every style, colors, a bag priced per category changed and paid in cash or bank (`clothing-shop` / `barber-shop`, prices only in `server/config.lua`), and My looks (illenium's `player_outfits`, saved from the paid look in the database, worn free). Everything is previewed on the frozen ped under a scripted camera; on pay the client sends only the categories changed in the shop (so a uniform worn over the look isn't saved) and the server builds the new `playerskins` look with `shared/look.lua` (tested: ranges, blocked pieces, prices). The pictures come from the **photo tool** (Staff app, `clothingPhotos`, admin): the staff member's ped is dressed one piece at a time in a routing bucket under Mission Row, in front of a drawn backdrop, and the server captures each one with screencapture into `images/<sex>_<c|p|o><slot>_<style>.webp` plus `images/index.json` (gitignored, made on the server; skips what exists, Backspace stops). Run `ensure city_clothing` afterwards so clients get the new files.
- **`city_mining`** (`[local]/`) is mining, the second legal job: anyone with a `mining_license` item of their own sells ore and uses the smelter. Veins only appear on points staff place with `/miningpoints` (`city_mining_points`; a region's area comes from its points), each region replicated in its own `GlobalState['mining:<region>']` and drawn by clients as local rocks with ox_target. The server owns every result (`server/mine.lua`: start → strike minigame → finish with session, time and distance checks; drops from `server/rolls.lua`, pure and tested). Four vein tiers unlocked by level (`gear.tierLevels`) and pickaxe tier; smelting orders in `city_mining_orders` (public smelter stamps ingots with `metadata.stamped`, home furnaces inside qbx_properties don't); geodes, gem cutting (1-3 stars in `metadata.quality`) and jewellery at Vangelico; panning and the sluice box; dynamite (the police grant `metadata.licences.explosives` in the MDT) for super rocks and the blocked passage, cave-ins with `state.miningTrapped`; a crime buyer that moves daily (`GlobalState.miningBuyer`). XP, levels and the skill tree reuse fishing's `shared/levels.lua` design (`city_mining_profiles`, written every minute); hidden daily luck in `server/luck.lua`. Money is `mining-*` reasons. The **Mining** tablet app is `web/app/`. Design: `docs/city-mining.md`.
- **`city_robbery`** (`[local]/`) is the robberies: ATMs blown with the `c4` item (ox_target on the ATM models; plant, then a fuse timed on the server) and 24/7 registers (an ox_target zone at each `General` location of city_inventory's `data/shops.lua`, read with `require '@city_inventory.data.shops'`). Each player has one robbery going at a time (`server/common.lua`), checked for time, distance and down; cooldowns are per ATM (anything within `Config.Atm.sameDistance`, since the server can't see map props) and per store. A store needs `Config.Store.minPolice` officers on duty, or staff with `Config.StaffAce` (shown the same notice plus "Staff overriding rule", written to the staff log). Payouts are in `server/config.lua` (ATM: base plus a share per officer on duty, `server/payout.lua`, tested). The cash is a bag on the floor (`GlobalState.robberyBags` holds only where they are; the amount stays on the server) that anyone picks up as cash with reasons `robbery-atm` / `robbery-store`; police calls go through `exports.city_police:Alert`.
- **`city_orgs`** (`[local]/`) is the criminal factions: qbx gangs created at start from `Config.Apps` (guns `arma1..3`, ammo `muni1..3`, contraband `contra1..3`), each with a vault stash at its QG and a tablet app named after the faction (one registration per gang, all on one page; the server resolves the faction from the viewer's gang). Staff puts the first players in a faction from the Staff app; the leader (isboss grade) recruits from the app's Management tab (gang copy of the Mechanic app's). The Vault tab shows the stash's items read-only (items only move at the QG) and the organization's money: any member deposits from their bank, only the leader withdraws, through city_bank's `Org*` exports (`settings.orgs` allowlist, reasons `bank-org-*`, account kind `gang` in city_economy). The Goals tab is the farm meta: the leader sets a daily and/or weekly goal over the app's `farmItems` (`farm_test1`/`farm_test2` for now; staff adds future farm items to the config), per item or as one sum across them; progress per member is deposited − withdrawn, counted from city_inventory's `city_inventory:server:stashMoved` event (fired in `server/other.lua` whenever a player moves items between their pockets and any stash) into `city_orgs_farm`, with both numbers shown side by side plus a contribution ranking, so cycling items in and out is visible. Activity (`city_orgs_log`) keeps vault moves, money, recruits and goal changes. qbx_management was removed (jobs manage themselves in the Mechanic/EMS apps and the MDT; `player_jobs_activity` stays in the database unused).
- **`city_ui`** (`[local]/`) holds the shared look of every screen in `theme.lua` (accent yellow, panel colors, radius, fonts). Resources load it with `require '@city_ui.theme'`, send it to their NUI page, and the page turns each key into a CSS variable (`accentText` → `--accent-text`); see `city_inventory/web/js/util.js` `applyTheme`. Don't hard-code those colors in a page's CSS, and don't use `backdrop-filter`: FiveM's NUI can't blur the game behind the page and draws it black.

## Writing our own resources

Custom code lives in `server-data/resources/[local]/` (`city_base` is the starter template; `city_inventory/server/commands.lua` has example admin commands). Conventions used there:

- `fxmanifest.lua` with `fx_version 'cerulean'`, `game 'gta5'`, `lua54 'yes'`, `@ox_lib/init.lua` as a shared script, and `dependencies { 'ox_lib', 'qbx_core' }`. Layout: `config.lua`, `client/main.lua`, `server/main.lua`.
- Use ox_lib helpers (`lib.addCommand`, `lib.notify`, `lib.print`, `cache.ped` / `cache.vehicle`) and Qbox exports (`exports.qbx_core:Notify`, `IsOptin`, …).
- Staff tools go in the Staff app (`city_staff`), not in-game commands. Test/dev commands that remain use `restricted = 'group.admin'` (the `IsOptin` check they still call is always true now that admin duty is off), with `source == 0` allowed for the server console.
- Net events are namespaced `<resource>:client:<name>` / `<resource>:server:<name>`. The player-loaded hook is `QBCore:Client:OnPlayerLoaded` (via the Qbox bridge).
- Qbox scripts (`qbx_*`) go in `[qbx]/`, framework-independent third-party scripts in `[standalone]/`, MLOs/map edits in `[maps]/`.
- Parts of a resource left out of the current version are `Config.Features` flags in its `config.lua` (shared): off, the client hides them (menus, zones, tablet tabs) and every server handler for them returns early, so a modified client gets nothing either. city_police, city_prison, city_fishing, city_mining, city_bank (loans, savings, scheduled transfers), city_dealership (financing) and city_mechanic (`chargeJob`) have them; the V1 test also stops qbx_properties, city_builder and the Militech tuners at the end of `server.cfg`. `bash scripts/wipe-db.sh` empties player data between test rounds (`docs/docker.md`).

## Skills

Project skills in `.claude/skills/` hold the step-by-step workflows: `new-resource` (a new `city_<feature>` script), `add-item` (items, weapons, shops, recipes), `patch-script` (changing a vendored script), `replace-script` (our resource replacing a vendored one, which is then removed everywhere) and `ship` (checks, NUI preview, commit, in-game test steps). Keep them in step when these workflows change.

`docs/skills.md` lists every skill (ours and not ours) with its name, description and location. As soon as someone starts a new skill, or renames, moves or removes one, run the `skill-registry` agent (`.claude/agents/skill-registry.md`) so the list stays complete.
