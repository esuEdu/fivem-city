# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A FiveM (GTA V) roleplay server on the **Qbox** framework (`qbx_core`) with the scripts of the Qbox txAdmin recipe (jobs, garages, HUD, illenium-appearance, …), the **ox** stack (oxmysql, ox_lib, ox_target, ox_doorlock, ox_fuel), our own inventory `city_inventory` (replaces ox_inventory) and pma-voice. All code is Lua 5.4 resources loaded by FXServer; there is no build step. `bash scripts/check.sh` checks our `[local]` resources without a server (Lua syntax, UI JavaScript, locale JSON, and the plain-Lua unit tests in `tests/<resource>/`, run with luajit); the rest is verified by restarting the resource on a running server.

## Running the server

FXServer is x86_64 only and **does not run on Apple Silicon** (crashes under Rosetta and QEMU). On a Mac, edit resources here and run the server on an x86_64 Windows/Linux machine.

```sh
cp .env.example .env                 # set CFX_LICENSE_KEY and MYSQL_ROOT_PASSWORD (alphanumeric only)
docker compose up -d --build         # FXServer + txAdmin, and MariaDB
docker compose logs fxserver | grep -i pin   # txAdmin PIN, then http://localhost:40120
docker compose logs -f fxserver
docker compose restart fxserver
docker compose build --no-cache fxserver && docker compose up -d   # update FXServer build
```

In the txAdmin wizard choose **Existing Server Data** → `/server-data`, config `server.cfg` — not a recipe, which installs its own copy under `/txData` that ignores this repo. txAdmin starts the server (the image entrypoint has no `+exec`).

Docker only imports `qbx_core.sql` into a new database. Create the other resources' tables with `scripts/import-sql.sh` (safe to re-run; run it after adding resources that bring SQL).

After editing a resource, reload it from the txAdmin console or in-game: `ensure <resource_name>` (or `restart`).

The full run guide (setup, updates, backups, troubleshooting) is `docs/docker.md`; keep it in step with changes to the Docker setup.

## Architecture

- **`server-data/server.cfg`** is the single entry point. It `exec`s `secrets.cfg`, then `ensure`s core resources in a fixed order (`oxmysql` → `ox_lib` → `qbx_core` → `city_ui` → `city_inventory` → `ox_inventory` → `ox_target`), then whole groups: `[ox]`, `[qbx]`, `[standalone]`, `[voice]`, `[assets]`, `[maps]`, `[local]`. Convars follow the Qbox recipe's `server.cfg` / `ox.cfg` / `voice.cfg`. Dropping a resource into one of those group folders is enough to start it. Framework/inventory convars (`qbx:enableBridge`, `inventory:framework "qbx"`, `inventory:accounts` left unset so it defaults to `["money"]`: the cash item is the player's cash) and ACE permissions (`group.admin` > `group.mod` > `group.support`) are also set there.
- **Secrets**: `secrets.cfg` is gitignored. In Docker, `docker/fxserver/entrypoint.sh` regenerates it on every start from env vars (license key, `mysql_connection_string` pointing at host `mariadb`). If `CFX_LICENSE_KEY` is empty, an existing mounted `secrets.cfg` is used instead.
- **Docker**: `docker-compose.yml` is the only way the server is run. It bind-mounts `./server-data` into the container, so the server runs the repo's files (FXServer itself is downloaded inside the image, never from `artifacts/` — Windows filesystems break its symlinks). MariaDB imports `qbx_core/qbx_core.sql` only when its volume is first created.
- **Third-party resources are vendored** (committed). `scripts/install-resources.sh` re-downloads everything the Qbox txAdmin recipe (`qbox.yaml`) installs except ox_inventory, wiping each target folder first, copies the qbx_invimages item images into `city_inventory/web/images`, then applies `scripts/patches/<resource>.patch`. Don't hand-edit those resources without a patch, or the change is lost on the next update: edit, then `bash scripts/make-patch.sh "server-data/resources/[group]/<resource>"`, which rebuilds the resource's whole patch from upstream (a bare `git diff` would drop the existing patch's changes).
- **`city_inventory`** (`[local]/`) replaces ox_inventory. qbx_core is hard-wired to ox_inventory, so `scripts/patches/qbx_core.patch` points it at `city_inventory`, which provides the same server/client export names and arguments (`AddItem`, `RemoveItem`, `GetItemCount`, `Search`, …) and the same `data/items.lua` / `data/weapons.lua` format (qbx_core loads those files too, so they must stay plain data). Make items usable with `exports.qbx_core:CreateUseableItem`. Inventories are saved in the `city_inventories` table, keyed by citizenid. `data/items.lua` is Qbox's item list; its ox-style `client.status/anim/prop/usetime/event/add/remove` fields work (`server/use.lua`, `client/use.lua`). Item names are case-insensitive (`WEAPON_PISTOL` = `weapon_pistol`) and stored as written in `data/`. Dropping one item onto another combines them on the server (`server/actions.lua` `combine`): ammo loads a gun, an attachment goes on a gun (kept in `metadata.components`), and `Config.Recipes` pairs craft; a gun's weight includes its attachments and loaded rounds (`shared/weight.lua`). Its `server/compat.lua` / `client/compat.lua` hold the less common ox exports and fire ox's events (`ox_inventory:currentWeapon`, `itemCount`, `openedInventory`). Stashes work (`RegisterStash`, `openInventory('stash')`, `forceOpenInventory`, `registerHook('openInventory')`; `server/stashes.lua`, shown as a second panel and saved in `city_inventories` as `stash:<id>`). Shops work too: `data/shops.lua` (ox_inventory's default stores, with blips and ox_target zones from `client/shops.lua`) plus `RegisterShop` from scripts (ambulance armory); items are bought by dragging them out of the shop panel, paid from `Config.ShopAccounts` or an item `currency`, with licence/grade/stock checked in `server/shops.lua`. Ground drops (`server/drops.lua`, bags from `client/drops.lua`, in memory for `Config.DropMinutes`; `CustomDrop`/`CreateDropFromPlayer`) and player trades (`server/trades.lua`: ox_target "Trade" on a player, both offers held aside as small inventories until both accept) work too; `server/other.lua` keeps one of stash/shop/ground/trade/search open per player. Trunks and gloveboxes are stashes keyed by plate (`server/vehicles.lua`, sizes in `Config.VehicleStorage`; saved only for cars in `player_vehicles`), opened with TAB at a car's back or inside it. Searching players (`openNearbyInventory`, `openInventory('player', id)`; `server/searches.lua`) shows the target's inventory as the second panel: police on duty (`Config.SearchJobTypes`) search anyone close, anyone may rob a player who is cuffed, down or has `state.handsup`, and staff with `Config.SearchStaffAce` on admin duty open anyone's from anywhere. The `money` item (`Config.CashItem`) **is** the player's cash: qbx_core mirrors city_economy's cash balance into it, scripts add or take it through qbx money (`server/cash.lua`), and every move inside the inventory (ground, trade offers, stashes, trunks, another player, death drop, clearing, expiry) is written to the ledger first by `server/cashflow.lua` (the hook in `Inventory.transfer`; if the ledger refuses, the item does not move). Scripts can't add/remove/set cash in stashes, drops or trades, and `players.sync` puts a pocket back to the ledger value (with a flag) if they ever differ.
- **`ox_inventory`** (`[local]/`) is a stand-in, not the real resource: two files that forward ox's export names to `city_inventory`, for the ~40 vendored scripts that call `exports.ox_inventory` and for ox_fuel, which needs a resource named ox_inventory at version ≥ 2.30.0. It has no logic of its own; our `[local]` resources call `exports.city_inventory` directly.
- **`city_economy`** (`[local]/`) owns all money: an append-only double-entry ledger (`economy_accounts`, `economy_ledger`) with atomic, locked postings. `qbx_core`'s `AddMoney` / `RemoveMoney` / `SetMoney` for `cash` and `bank` ask it first (`scripts/patches/qbx_core.patch`) and `PlayerData.money` is only a mirror (`SetPlayerData('money')` is refused, `crypto` is gone). It only accepts the resource + reason pairs listed in `city_economy/server/config.lua` `sources`; anything else is refused and logged, so a script that pays or charges must pass a reason and be added there. New characters get $2,000 cash and $18,000 bank from it. Rules and design: `PROMPT_ECONOMIA_FIVEM.md`, `BANCO_DESIGN.md`; blocked scripts are listed in `docs/scripts/issues.md`. **`city_bank`** is the bank on top of it: branches (banker NPC, fingerprint, panel with accounts, cards, transfers, loans, bills, history, staff tab), ATMs, the `bank_card` and `pos_terminal` items and a scheduler (bills, card cycles, installments, savings yield). It moves money only through `city_economy` `Bank*` exports (reasons `bank-...`, callable only from city_bank); rules and numbers are in `city_bank/server/config.lua`. Renewed-Banking was removed. Other resources bill players with `exports.city_bank:CreateBill` only if listed in its `settings.billers`. The phone's Wallet (`city_phone_wallet`) uses the same panel handlers through `city_bank:app:<name>` (`access.allowApp` in `server/app.lua`: phone item and not down instead of branch + fingerprint); a card purchase over the card's own limit asks its holder on the phone (`server/approvals.lua`, `settings.app.approvalSeconds`) and is paid only if approved.
- **`city_hospital`** (`[local]/`) replaces qbx_ambulancejob; qbx_medical still owns injuries and the death state bag (`qbx_medical:deathState`, set by the client). city_hospital tracks downed players on the server from that bag, turns off qbx_medical's own respawn, and owns the downed screen (NUI), `/finalizado` (character metadata `finalized`, which only a real revive clears: `scripts/patches/qbx_medical.patch` fires `qbx_medical:server:revived`), hospital respawn, beds, reception, the NPC ambulance and the EMS job. Other medic scripts must check `exports.city_hospital:IsFinalized(src)` before reviving. Fees are `hospital-*` reasons; unpaid ones become bills. Prices and timers are in `server/config.lua`.
- **`city_garages`** (`[local]/`) replaces qbx_garages. Garages are unified: a car parked at any garage of its kind (`car`/`air`/`sea`, from the qbx_core vehicle `type`) can be taken out at any other, so `player_vehicles.garage` is only where it was last parked. Players open a garage with ox_target on its ped and park with ox_target "Park vehicle" on their empty car inside the parking area; the NUI lists their cars with search, favorites (client KVP) and the model's picture (`Config.ImageUrl`, docs.fivem.net) and condition. Impound lots (`depot = true`) return cars left out that are no longer in the world for a fee (`garage-depot`, cash then bank); police-impounded cars (`state = 2`) are not theirs. Other scripts add garages with `exports.city_garages:RegisterGarage(id, { label, kind, coords, spawns, canAccess, ... })`; qbx_properties does it for house garages (`scripts/patches/qbx_properties.patch`).
- **`city_dealership`** (`[local]/`) replaces qbx_vehicleshop: Premium Deluxe Motorsport only (no boat or air shop). ox_target on a showroom computer (`Config.Computers`) opens the catalogue NUI: every car of `Config.Categories` from qbx_core's vehicle list (price from there, `Config.Blocklist` skipped), photo from `Config.ImageUrl`, stats from the model's handling natives, test drives (server-spawned on the lot, deleted after `Config.TestDrive.seconds` or when too far). Buying in full (cash or bank) or financed (`server/quote.lua`: down payment, interest, installments) is `dealership-*` reasons; the car is created parked at the `pdm` garage of city_garages. Each installment is a city_bank `loan` bill issued with `exports.city_bank:IssueBill` (offline-safe, for `settings.billers`); every minute `server/finance.lua` reads the bills' status in `bank_bills`, closes paid-off financings and repossesses the car (deleted from `player_vehicles`) once `Config.Finance.repoAfter` bills are overdue. Exports `FinanceBalance` / `IsFinanced`, for scripts that sell or trade owned cars. The old `vehicle_financing` table is no longer read.
- **`city_mechanic`** (`[local]/`) replaces qbx_mechanicjob and qbx_customs: the `mechanic` job at LS Customs (Burton), with duty, a shared stash, work vehicles and the tuning bay. A mechanic on duty drives the car into `Config.Bay` and presses the keybind (E) to open the NUI menu; every choice is previewed on the car (the driver owns the entity), and on confirm the server checks the cart against `shared/catalog.lua` (keys are ox_lib vehicle property names), prices it from `Config.Prices`, pays it from the mechanic job's account with `exports.city_bank:ChargeJob` (only resources in city_bank `settings.jobPurchases`; reason `bank-job-purchase`, money goes to `WORLD_SINK`) and writes the paid changes into the car's saved props itself (`qbx_vehicles` `SaveVehicle`). The mechanic charges the customer separately (bill or card machine). `repairkit`, `advancedrepairkit` and `cleaningkit` are usable by anyone next to a car; mechanics on duty fix more. qbx_mechanicjob's part wear (radiator, axle, ...) is gone; `player_vehicles.status` / `drivingdistance` are no longer read.
- **`city_phone`** (`[local]/`) replaces npwd. It opens from the `phone` item and always shows its user's own data (number = `charinfo.phone`; settings in metadata `phonesettings`). It is only the platform (lock screen, home, dynamic island, control center, multitask, Settings, notifications): every app is its own `city_phone_<app>` resource that calls `exports.city_phone:RegisterApp` on the client; the phone shows the app's page in a frame and passes `city_phone:context` / `city_phone:message` with postMessage, and the page calls its own resource's NUI callbacks. Old `qb-phone:*` mail and alert events become phone notifications (`server/compat.lua`, `client/compat.lua`). Ringing is the `phoneRinging` state bag (`exports.city_phone:SetRinging`), played by everyone nearby with Web Audio tones. `city_phone_calls` is the Phone app; it is the only resource that sets pma-voice call channels, and it puts back anyone who joins a call channel on their own, and exports `Contacts` / `ContactName` for other apps. Its contacts also list the city services from **`city_dispatch`** (`Config.Services`: 190 police, 192 EMS, mechanic), fixed and not editable: calling one (or dialing the number) opens a form (type, text, anonymous) and `exports.city_dispatch:Report` sends it with the caller's location to that job type on duty (phone notification with a Respond button, blip, `/calls`), or for EMS into city_hospital's calls (`exports.city_hospital:PhoneCall`). Responders are never named to the caller. `city_phone_messages` is Messages: chats keyed by phone number (so offline players get them later), groups, reactions, read receipts, and locations read on the server (live shares update a blip every few seconds; the route set on the map can be sent too, its point checked against `Config.MapBounds`). `city_phone_gps` is Maps: it has no map of its own but puts the phone away and opens the game's pause-menu map (`FE_MENU_VERSION_MP_PAUSE`), bringing the phone back when it closes, and its page shows or clears the route. Apps show unread counts with `exports.city_phone:SetBadge`. `city_phone_darkchat` registers DarkChat only while its client carries the `darkchat_usb` item (`RemoveApp` when it goes) and its server checks the item on every callback; rooms are joined by exact name (password hashed with `GetPasswordHash`), others only see aliases, and messages are deleted after `Config.MessageHours`. `city_phone_news` is Weazel News: only jobs in its `Config.Jobs` (reporter) on duty write; breaking news notifies every online player, at most once per `Config.BreakingCooldown` minutes per journalist; the author, the job's boss and `Config.StaffAce` delete (staff through `exports.city_staff:Log`). `city_phone_music` plays inside its own page (a hidden YouTube iframe player, or an `<audio>` for https audio links; app frames get `allow="autoplay"`), so only the owner hears it and it keeps playing with the phone closed until the app is closed from the switcher; searching by title goes through the server with the convar `youtube_api_key` (from `YOUTUBE_API_KEY` in `.env`), and pasted YouTube links get their title from oEmbed. App pages share one look through the kit in `city_phone/web/kit/` (`kit.css` + `kit.js` with icons, lists, avatars, sheets, nav bars, tab bar), loaded from `https://cfx-nui-city_phone/web/kit/`; use it for every new app. The phone size (70–130%) is a setting, also changed by dragging the phone's top-left corner. `city_phone_camera` (camera mode: scripted back camera, the game's selfie camera, timecycle filters) asks `city_phone_photos` to take the picture; the server captures it with `exports.screencapture:serverCapture`, checks size and the 300-photo limit, and keeps it in `phone_photos` (the client never uploads an image). A photo can be the wallpaper (setting `wallpaperPhoto`); other apps read a character's photos with its `List` / `Data` exports. `city_phone_market` is Market: ads in `phone_market_ads` (the chosen photo is copied into the ad) and `phone_market_favorites`; publishing or renewing costs `Config.Fee` from the bank (city_economy reason `market-ad`), ads expire after `Config.Days`, `Config.MaxAds` per character, "Contact" opens the seller's chat in Messages, and `Config.StaffAce` removes any ad (written to the staff log through `exports.city_staff:Log`). `city_phone_social` is InstaPic: one account per character in `phone_social_accounts`, posts and 24-hour stories in `phone_social_posts` (the chosen photo is copied in), likes, comments and follows in their own tables; likes, comments and new followers notify the person on the phone, and `Config.StaffAce` removes any post or comment (staff log through `exports.city_staff:Log`). `city_phone_dating` is Matchy: profiles (`phone_dating_profiles`, age and gender from charinfo, up to 3 photos copied into `phone_dating_photos`), swipes, matches and a chat of their own; pages only see a profile's numeric id, never a citizenid or phone number.
- **`city_os`** (`[local]/`) is the iFruit tablet (`tablet` item, F2): lock screen, passcode, home, dock, notification center and the built-in Settings, and nothing else. Every app is its own resource: it registers on the server with `exports.city_os:RegisterApp` (glyph + colors icon, its own `web/` page loaded in an iframe, access by job/gang/staff/unlock), styles its page with `city_os/web/kit/kit.css` + `kit.js`, and uses `Notify`/`SetBadge`/`Unlock`; its own server events still check access. Tablet settings and the bcrypt passcode are saved per serial in `city_os_tablets`; a player's own wallpaper link stays in client KVP. Design: `docs/city-os.md`.
- **`city_staff`** (`[local]/`) is the first tablet app, **Staff**, and replaced qbx_adminmenu: player list and actions, `/report` reports, warnings (`city_staff_warnings`), bans (qbx_core's `bans` table), the staff log (`city_staff_log`), noclip/names/blips and vehicles. Staff tools live only in the app, with no in-game commands; `qbx_core.patch` also removes qbx_core's admin commands and turns admin duty off (`requireOptIn = false`, no `/optin`, so `IsOptin` is always true). Levels are the `support` < `mod` < `admin` ACEs; what each may do is `Config.Permissions`, checked by every server callback (`server/staff.lua` `staff.register`). Design: `docs/city-staff.md`.
- **`city_police`** (`[local]/`) replaced qbx_police: the LSPD job and the **MDT** tablet app. Only the `police` job exists (BCSO and SASP are removed by `qbx_core.patch`, which also makes officers clock in). It owns the police calls (`exports.city_police:Alert`, `PhoneCall` from city_dispatch for 190, the panic button), cuffs (`metadata.ishandcuffed`, set only on its server; `exports.city_police:SetCuffed` / `IsCuffed`), escort, objects and spike strips (`GlobalState.policeSpikes`), ground evidence (casings, blood, fingerprints; bags analyzed in the MDT), security cameras, ankle monitors, speed cameras, impounds (`player_vehicles.state = 2` until released) and the records in its `city_police_*` tables. Fines, radar tickets and impound fees are city_bank bills, never direct money. It keeps the old qbx_police events vendored scripts still fire (`police:server:policeAlert`, `evidence:server:CreateFingerDrop` / `CreateBloodDrop`, `evidence:client:SetStatus`, `police:client:SendPoliceEmergencyAlert`, `police:SetCopCount`, the camera events). Weapons bought in a shop are registered by serial (city_inventory fires `city_inventory:server:boughtWeapon`; `exports.city_police:RegisteredWeapons(citizenid)`). An arrest shows the arrested screen and calls `exports.city_prison:Jail`. Other scripts add warrants with `exports.city_police:IssueWarrant`. Grades per action are `Config.Permissions`; design: `docs/city-police.md`.
- **`city_prison`** (`[local]/`) replaced xt-prison: Bolingbroke. Sentences are counted on the server (one month = one minute played inside, `server/config.lua`) in `city_prison_inmates`, with `city_prison_log` as history; `metadata.injail` only mirrors the months left and `Player(src).state.inPrison` says who is inside. Going in, the inmate goes off duty (and can't clock in), wears the uniform and their items go to a per-character `city_prison_locker` stash, except illegal ones and weapons not registered to them, which go to city_police's evidence locker; cash stays in the pocket. Jobs (cleaning, kitchen, electrical) take months off up to half the sentence; water and a food tray feed them; hidden spots give parts that combine (city_inventory `Config.Recipes`) into a shank, a gate jammer or a `burner_phone`. Leaving the circle is an escape: the time left times `escapeMultiplier` is owed, the police get a call and an MDT warrant, and the next arrest adds it. Gate terminals open ox_doorlock gates it creates by name. A downed inmate wakes in the prison infirmary (`exports.city_prison:Respawn`, called by city_hospital). Police on duty use the prison computer (list, set time, release, clear an escape; grades in `Config.ComputerGrades`). When the time is served the inmate is let out automatically: prison-made items stay inside and the locker comes back (the release desk only hands out what didn't fit). A burner phone is city_phone with its own number (in the item metadata), calls always hidden and only `Config.BurnerApps`; Phone and Messages get the number in use from `exports.city_phone:ActiveNumber` / `SourceByNumber`. Design: `docs/city-prison.md`.
- **`city_drugs`** (`[local]/`) replaced qbx_drugs and qbx_weed: weed, cocaine and meth, from pick spots (`Config.Fields`, regrowing, picked state in `GlobalState.cityDrugsPicked`) to the biker-business labs (bob74_ipl interiors entered through a door; `Config.Labs` keyed by drug) to corner sales and bulk deals, paid in `black_money`. Every timed action is clocked on the server (`server/common.lua` `start`/`finish`). Labs and deals are for the drug gang only (`server/config.lua` `gangOnly`, gangs from city_gangs `Config.Gangs`). Risk is per drug (`drugs` in `server/config.lua`): a police call (`exports.city_police:Alert`) has the drug's base chance per act, plus a point per `perPoint` dollars of a sale, capped at `max` (`server/rules.lua` `risk`). Sales and batches are reported to city_gangs (`exports.city_gangs:Record`); `exports.city_drugs:Guide()` is the chain as the Gang app shows it.
- **`city_gangs`** (`[local]/`) is the drug gang's tablet app (label **Cartel**), built like city_staff and registered only for the gangs in `Config.Gangs` (default `cartel`); other gangs will get their own apps for their own business. Those gangs are also the only ones city_drugs lets into its labs and bulk deals (`exports.city_gangs:IsDrugGang`). `server/gang.lua` `gang.register` wraps every callback with the member's gang and a grade check (`Config.Permissions`, lowest grade per action). Dashboard: the gang's money, sales, units made and active members for a period (`Config.Periods`), a daily chart (`Config.ChartDays`), per drug, and a ranking of every member; each member's page has their own numbers, place and share in the gang, chart, per drug and activity. Members come from qbx_core (`GetGroupMembers`, `AddPlayerToGang`, `RemovePlayerFromGang`); you only manage members below your own grade, and nobody is made boss from the app. Recruiting invites a nearby player with no gang, who accepts on their own screen (checked again on the server). Everything is counted from `city_gangs_log`: hires, rank changes, and the sales and batches `Record` gets from resources in `Config.RecordFrom`.
- **`city_ui`** (`[local]/`) holds the shared look of every screen in `theme.lua` (accent yellow, panel colors, radius, fonts). Resources load it with `require '@city_ui.theme'`, send it to their NUI page, and the page turns each key into a CSS variable (`accentText` → `--accent-text`); see `city_inventory/web/js/util.js` `applyTheme`. Don't hard-code those colors in a page's CSS, and don't use `backdrop-filter`: FiveM's NUI can't blur the game behind the page and draws it black.

## Writing our own resources

Custom code lives in `server-data/resources/[local]/` (`city_base` is the starter template; `city_inventory/server/commands.lua` has example admin commands). Conventions used there:

- `fxmanifest.lua` with `fx_version 'cerulean'`, `game 'gta5'`, `lua54 'yes'`, `@ox_lib/init.lua` as a shared script, and `dependencies { 'ox_lib', 'qbx_core' }`. Layout: `config.lua`, `client/main.lua`, `server/main.lua`.
- Use ox_lib helpers (`lib.addCommand`, `lib.notify`, `lib.print`, `cache.ped` / `cache.vehicle`) and Qbox exports (`exports.qbx_core:Notify`, `IsOptin`, …).
- Staff tools go in the Staff app (`city_staff`), not in-game commands. Test/dev commands that remain use `restricted = 'group.admin'` (the `IsOptin` check they still call is always true now that admin duty is off), with `source == 0` allowed for the server console.
- Net events are namespaced `<resource>:client:<name>` / `<resource>:server:<name>`. The player-loaded hook is `QBCore:Client:OnPlayerLoaded` (via the Qbox bridge).
- Qbox scripts (`qbx_*`) go in `[qbx]/`, framework-independent third-party scripts in `[standalone]/`, MLOs/map edits in `[maps]/`.

## Skills

Project skills in `.claude/skills/` hold the step-by-step workflows: `new-resource` (a new `city_<feature>` script), `add-item` (items, weapons, shops, recipes), `patch-script` (changing a vendored script), `replace-script` (our resource replacing a vendored one, which is then removed everywhere) and `ship` (checks, NUI preview, commit, in-game test steps). Keep them in step when these workflows change.

`docs/skills.md` lists every skill (ours and not ours) with its name, description and location. As soon as someone starts a new skill, or renames, moves or removes one, run the `skill-registry` agent (`.claude/agents/skill-registry.md`) so the list stays complete.
